# Changelog — 2026-10-08

## Bom Dia, Artisan plugin — initial build (v0.1.0)

- **Status:** ✅ Completed (reviewed)
- **Scope:** new repo `omarchy-bom-dia-artisan` · Omarchy Quickshell bar widget `m0u.artisan` · branch `main`
- **Summary:** Built an Omarchy bar widget that brings the bom-dia-artisan.dev daily Laravel
  digest into the bar: a mug that steams when an edition is unread, and a panel that reads the
  whole edition in place.

### Changes
- **Data source:** `GET https://bom-dia-artisan.dev/api/reports` (JSON, 16 editions, ~130 KB),
  not `/feed.xml`. The RSS feed carries a title and one paragraph per edition. The JSON carries
  every section, item, status and link. Older editions with no `status` field are inferred from
  a leading "Released"/"Merged" in the description.
- **Bar mark (`Mark.qml`):** a mug glyph. When an edition is unread, steam rises and a
  Laravel-red dot appears, with a count when more than one edition is unread. The mug dims when
  offline or stale. Left-click opens the panel. Middle-click opens today's edition on the site.
- **Panel (`Panel.qml`, `ItemRow.qml`, `StatusChip.qml`):**
  - The header is a day navigator (‹ Hoje ›) with an unread dot.
  - Filter chips: Tudo / Releases / Merged / Dicas.
  - Below them come the editors' summary, the "atenção" box, and the items grouped by package,
    with the recommendation last.
  - Each item shows a status chip, its repo, the title, why it matters, and the full note on
    Space. Its own ↗ opens the source.
  - Keyboard-first: arrows/hjkl, Space, Enter, g/G, f/F, 1–4, n, o, r, m, Esc, Tab.
  - An edition counts as read after 1.2 s on screen.
- **Header actions:** the panel title is the link to the site. On hover a brand underline grows
  under it and a ↗ pops in, in a slot reserved at rest so nothing shifts. A ↻ beside it fetches
  now and spins while busy. The footer's "Abrir no site" and refresh buttons were removed.
- **Once-a-day check:** at `checkAt` (default 09:30), because the user wants a quick morning
  brief, not a ticker.
  - A late edition is retried hourly. A failed request retries after 1 min, doubling up to
    30 min.
  - Opening the panel never fetches.
  - `Source.checkDue()` runs on a 60 s wall-clock tick, so suspend cannot delay it.
- **Multi-monitor:** one instance per monitor. Only the leader (`bar.moduleWidgets()[0]`)
  fetches and notifies. The others sync from the watched cache and state files. Panel IPC goes
  through `runOnFocused`.
- **Toast:** `notify-send` with a "Ler" action that opens the panel over IPC. It is sent once
  per edition and respects Do Not Disturb. On a first run, everything but the newest edition is
  seeded as read.
- **Settings:** `checkAt` (HH:MM) and `notify` (on/off).
- **Bar layout:** the widget is placed before `m0u.backups` in `~/.config/omarchy/shell.json`
  (backup `shell.json.bak.<ts>`).

### Verification
- `npm test`: 29 pass. The tests run the shell's own JS against a real `/api/reports` capture
  (16 editions, 145 items), and `tools/escape-glyphs.py --check` runs as part of it.
- `omarchy plugin validate .` passes, and the shell log is clean after `omarchy restart shell`
  (only the expected duplicate-IpcHandler warning for the second monitor).
- Live checks:
  - First fetch, cache and seeding gave unread badge "2".
  - Checked in the panel: cursor, expanded note scrolled into view, day navigation, dwell
    mark-read, filter shrinking the panel, and theme adaptation.
- Daily check:
  - A restart with today's edition cached made no request (the cache mtime was unchanged).
  - With today's edition removed from the cache, a restart made exactly one fetch, and the
    next tick made none.
- Header hover was checked with a screenshot taken while hover was forced on in the code for
  one restart, since a pointer warp sends no hover event to a layer-shell panel. The user then
  reviewed the real hover and click.

### Files
- `manifest.json`: id, entry point, settings schema (`checkAt`, `notify`).
- `BarWidget.qml`: the only file with I/O (curl, cache/state FileViews, toast, IPC, leader

## Review against the site's API docs: Markdown notes, 429, São Paulo dates

- **Status:** ✅ Completed (reviewed)
- **Scope:** Model / Source / BarWidget / ItemRow · branch `main`
- **Summary:** I reviewed the plugin against the new `llms.txt` and `/api-docs` and fixed the
  three findings. The editors' notes now render their Markdown, rate-limit replies (`429`) are
  honoured, and "today's edition" follows São Paulo's date.

### Review findings
- Matches the docs: `GET /api/reports`, every field read, the three statuses, and `generatedAt`
  in either offset. One check a day is far under the 10 requests/min limit, and the server sends
  no `ETag`/`Last-Modified` to make a cheaper request with.
- Undocumented but handled: `metadata.attention` (the "atenção" box hides itself without it) and
  old items with no `status` (inferred from the description).
- Fixed below: (1) `details` is Markdown and rendered as one run-on paragraph, (2) `--fail` hid a
  `429`, (3) "today" used the reader's local date.
- Deferred: late-day retries could use `GET /api/reports/{date}` (~10 KB, 404 until published)
  instead of the full list.

### Changes
- **`Model.markdown()`** converts Markdown to Qt StyledText: paragraphs, headings (bold, on
  their text), `•` and numbered lists, code blocks (monospace, accent colour, indentation kept),
  `[links](…)` and bare URLs (http(s) only), and `**bold**` / `*italic*`. Code spans and links
  are lifted out as placeholders first, so `**` inside code or `_` inside a URL is never styled.
- `ItemRow` renders notes with it. A link takes its own click (`linkRequested` →
  `Panel.openLink`), opens through the same http(s)-only `openUrl`, and closes the panel.
- **`Source.request()`** dropped `--fail` and appends a trailer:
  `--write-out "\n@@bom-dia-artisan %{http_code} %header{retry-after}"`. `parse()` reads it:
  - a `429` gives "O site pediu uma pausa…" and `retryAfterMs`, from seconds, an HTTP date, or
    a 60 s fallback;
  - any other non-2xx gives "O site respondeu com erro (HTTP n)".
- **BarWidget:** a `429` sets `notBeforeMs`. `checkDue` and the ↻ button both hold until then.
- **`Source.editionDate()`:** São Paulo's date from a fixed UTC-3 offset. `checkDue` now takes
  `newestDate` and treats the day as done when `newestDate >= editionDate(now)`.
- README: notes, politeness, São Paulo dating, the curl trailer.

- All 145 live notes converted with no raw fences, links, headings, `**` or leaked placeholders.

## Late-day retries probe one edition instead of the full list

- **Status:** ✅ Completed (reviewed)
- **Scope:** Source / BarWidget · branch `main`
- **Summary:** On a late day, the hourly retries now ask `GET /api/reports/{date}` (~10 KB,
  `404` until published) instead of re-downloading the full list (~130 KB). This is the item
  deferred in the API-docs review above. It was built by a parallel agent session and reviewed
  here before committing.

### Changes
- **`Source.planCheck({nowMs, checkAt, lastListOkMs, failures, force})`** returns
  `{kind:"list"}` or `{kind:"probe", date}`.
  - The answer is the list for the day's first check (no list since today's `checkAt`), after
    any failure, and for ↻ / IPC refresh (`force`).
  - Otherwise it probes São Paulo's `editionDate`.
  - `checkDue` still decides *when*.
- **`Source.request(kind, date)`** builds the probe URL. A date must match `^\d{4}-\d{2}-\d{2}$`;
  otherwise it returns `[]`, which the widget treats as a failure.
- **`Source.parse(…, plan)`**, for a probe:
  - `404` → `{ok, pending}`: not out yet, which is not a failure;
  - `200` with that date → `{ok, arrived}`;
  - any other `200` → failure ("O site respondeu outra edição");
  - `429` and curl errors → as before.
- **BarWidget:**
  - `refresh()` runs the plan, kept in `internal.plan`.
  - `probed()` clears `failures`/`error`. On `arrived` it fetches the list with
    `Qt.callLater(refresh(true))`.
  - Only a list is ever cached.
  - `internal.lastOkMs` (list-only, restored from the cache's `fetchedAt`) doubles as
    `lastListOkMs`, so a restart in the middle of a late day keeps probing.
- `test/source.test.mjs`: the glyph-check regex had literal private-use characters; they are now
  the `-` escape, with the same behaviour.
- README: politeness bullet, `checkAt` text, the "Late-day probe" row, data-flow step 2, and the
  `Source.js` map line.

### Verification
- `npm test`: 44 pass (8 new), also with `TZ=Asia/Tokyo` and `TZ=UTC`. Re-run here after the
  agent.
- `omarchy plugin validate .` passes.
- Live API through `Source.request()`, 3 requests:
